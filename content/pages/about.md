## 为什么写

写作是一种延迟满足的思考。很多以为自己懂了的东西，落到纸面上就会露出缝隙：定义没有说清，假设被悄悄换掉，结论其实只在很窄的条件下成立。

这个站点是我的外部记忆，也是一次公开的练习。它不追求覆盖多少主题，只记录那些值得反复理解的问题——某个结论究竟依赖什么，某个定理为什么成立，以及它在什么时候会失效。

目前先放了三篇笔记，分别从极限、线性映射与二次曲线开始。框架、排版与知识地图已经就位，内容会沿着这三条线慢慢长出来。

## 关心什么

大致沿着三条主线，以及它们的交界处：

- **数学分析**：极限如何用 ε–δ 说清楚，导数与积分在什么条件下可以交换，函数项级数何时收敛得足够好；
- **高等代数**：线性空间与线性映射如何脱离坐标，矩阵、特征值与二次型怎样把抽象结构变成可计算的对象；
- **解析几何**：向量、坐标与方程如何描述直线、平面、曲线与曲面，几何直觉又如何反过来解释代数结论。

比起记住结论，我更关心条件：一个定理的假设删掉一条，结论会在哪里坏掉。反例和证明一样重要。

## 怎么写

每一篇尽量回答三个问题：

1. **定义**——对象是什么？量词、条件与记号是否说清楚了？
2. **定理**——在哪些假设下，什么结论成立？哪一条假设是真正关键的？
3. **证明**——从假设到结论，每一步怎么接上？有没有反例说明条件不可省？

推导优先于结论，具体例子优先于术语堆叠。遇到不确定的地方，我会直接标出来，而不是用流畅的句子掩盖它。

## Colophon

这个站点没有使用现成的博客框架。它由一段几百行的 Node 静态生成器编译：

- 文章用 Markdown 写作，公式由 KaTeX 在构建时渲染为静态 HTML；
- 页面是手写的 HTML 与 CSS，客户端 JavaScript 只负责搜索、主题、目录与知识地图；
- 字体自托管，不依赖第三方 CDN；
- 托管在 GitHub Pages，每次推送自动构建部署。

完整源码与部署说明在仓库的 `README.md` 里。如果你想把它改成自己的站点，主要只需要编辑 `site.config.mjs`。

## 边界

这里的文字是学习过程中的整理，不是权威教材。错误一定存在，观点也会变化。如果你发现推导有问题，或者有更好的解释，欢迎在 GitHub 上开一个 issue。

> 把复杂的问题想清楚一点，就已经很不容易了。
